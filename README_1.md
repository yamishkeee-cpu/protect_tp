# protect_tp — Telegram-бот знакомств и поиска команд ВШЭ НН

Бот поддерживает постоянные профили пользователей, просмотр анкет с лайками и взаимной симпатией, временные анкеты для учебных задач/проектов и поиск мероприятий с откликами.

## Установка

Требуется Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate          # macOS/Linux
# .venv\\Scripts\\Activate.ps1     # Windows PowerShell
python -m pip install -r requirements.txt
```

## Токен и запуск

1. В `@BotFather` отзови прежний токен и выпусти новый: токен из предыдущей версии исходников уже был раскрыт и считается скомпрометированным.
2. Скопируй `.env.example` в `.env` и укажи новый токен либо задай переменную окружения. Не вставляй токен в Python-файлы и не отправляй его в Git.

```bash
cp .env.example .env        # необязательно, если задаёшь токен через окружение
# затем укажи BOT_TOKEN в .env; или используй команду ниже
export BOT_TOKEN='НОВЫЙ_ТОКЕН'  # macOS/Linux
python bot.py
```

В Windows PowerShell:

```powershell
$env:BOT_TOKEN='НОВЫЙ_ТОКЕН'
python bot.py
```

По умолчанию SQLite-файл `dating_bot.db` находится рядом с `db.py`, поэтому каталог запуска не влияет на выбор базы. Для отдельной базы можно задать `DATABASE_PATH` абсолютным путём.

## Основные сценарии

- **Поиск людей для общения:** просмотр анкет, лайк/пропуск, уведомление о взаимной симпатии.
- **Поиск для задач/проектов:** создание временной анкеты на 3 дня, просмотр анкет, отклик и закрытие собственных анкет.
- **Поиск мероприятий:** создание события, просмотр событий, отклики, просмотр откликнувшихся и закрытие своего события.
- **Мой профиль / Заполнить заново:** просмотр и повторное заполнение постоянного профиля.

Команда `/cancel` завершает текущее заполнение.

## Админ-панель

Вход: команда `/admin`. Админы назначаются по Telegram-юзернеймам: перед запуском задай в `.env`

```
ADMIN_USERNAMES=ivan_hse,maria_nn    # администраторы: всё (без @, через запятую, регистр не важен)
MODERATOR_USERNAMES=petr_nn          # модераторы: пользователи, жалобы, журнал (без бана навсегда, настроек и рекламы)
```

Каждый такой человек один раз пишет боту (например `/start`) — бот привязывает его Telegram ID к роли (запись в журнале «Назначение админа по username»). Дальше права проверяются по ID, поэтому смена юзернейма доступ не ломает. Чтобы отозвать доступ, убери имя из `.env` и перезапусти бота. Запасной вариант — `ADMIN_IDS` / `MODERATOR_IDS` с числовыми ID.

Разделы:

- **Пользователи** — поиск по Telegram ID, внутреннему ID, @username или имени из анкеты (часть имени подойдёт; если совпадений несколько, бот покажет список). Username сохраняется, когда человек пишет боту, поэтому для тех, кто не писал после обновления, он неизвестен. Карточка, временный бан (1/7/30 дней), бан навсегда, предупреждение, снятие блокировки, история санкций, переключатель статуса «зареган / не зареган».
- **Жалобы** — кнопка «🚩 Пожаловаться» под анкетой в ленте. Жалоба на **не зарегистрированный** аккаунт → мгновенный бан без модерации. Жалоба на **зарегистрированный** → очередь модератора: отклонить / предупредить / бан на срок / бан навсегда + комментарий модератора.
- **Настройки** — на каждой кнопке написано текущее состояние (🟢 ВКЛ / 🔴 ВЫКЛ, ✅ ЗАРЕГАН / 🕓 НЕ ЗАРЕГАН, число); по нажатию переключатель меняется и бот показывает новое состояние. Пункты: статус новых аккаунтов по умолчанию, лимиты лайков/пропусков/создания анкет, порог подозрительной активности и длительность временного ограничения. Всё хранится в БД и меняется без перезапуска.
- **Реклама** — карточка с пометкой «Реклама» между анкетами: текст, картинка, ссылка, кнопка, частота (1 на N анкет), лимит показов на пользователя, даты, статистика показов и нажатий. Запуск требует подтверждения.
- **Журнал действий** — все действия админов и автоматика (авто-баны, авто-ограничения) с фильтрами по админу, пользователю, типу и дате. Таблица `admin_actions` защищена триггерами от UPDATE/DELETE.

Таблицы админки: `accounts` (создаётся в `db.py`), `admins`, `settings`, `reports`, `sanctions`, `admin_actions`, `action_log`, `ad_campaigns`, `ad_impressions`, `ad_clicks`, `user_ad_state`.

Статус «зареган» хранится в `accounts.is_registered`. Когда в проекте появится подтверждение почты, достаточно вызвать `admin_db.set_registered(user_id, True, None, source="auto")` — это же автоматически снимет бан, выданный за «не зарегистрирован».

## Границы текущей версии

Сейчас реализованы регистрация постоянного профиля, лента анкет с лайками и взаимной симпатией, временные анкеты для задач/проектов, а также создание и поиск мероприятий с откликами. Пункты `plan.txt`, относящиеся к следующим этапам, ещё не реализованы: подтверждение почты, дополнительные фильтры поиска, согласие на обработку персональных данных, планировщик фоновых задач, а также редактирование и продление уже созданных мероприятий. Их не следует считать доступными в этой версии.

## Проверка без запуска Telegram

```bash
python -m unittest discover -s tests -v
```

Тесты создают отдельную временную базу и не меняют рабочий `dating_bot.db`.
